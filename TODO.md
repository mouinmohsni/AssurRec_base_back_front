# AssurRec — résultats de la phase applicative

Périmètre validé par Mouin : recouvrement de primes/cotisations impayées, nouvelle application distincte de Telecom-platform. La campagne pédagogique automatisée reste différée. Les cases ci-dessous désignent l’implémentation et les vérifications de construction, pas une certification ni une couverture exhaustive.

- [x] **Socle full-stack.** React/TypeScript appelle une API REST Express ; MySQL conserve les données ; migrations versionnées et seed fictif explicites/idempotents ; Docker et guide local fournis ; rien n’efface les données au démarrage. Routes et règles métier pures séparées ; services.ts orchestre les requêtes SQL (découpage en repositories plus fins possible ensuite). Aucun dépôt GitHub existant modifié. Typecheck/build exécutés ; Docker/Windows restent à exécuter dans la phase de portabilité.
- [x] **Connexion et trois profils protégés.** Connexion e-mail/mot de passe avec scrypt, sessions réelles, cookie HttpOnly, CSRF stable et limite d’essais. Administrateur gère comptes/rôles/configuration des accès ; gestionnaire contrats/échéances/affectation/supervision ; agent agit uniquement sur ses dossiers affectés. Aucun faux utilisateur Preview ni promotion publique. Connexions et refus de permissions vérifiés via API.
- [x] **Assurés, contrats et échéances.** CRUD et formulaires pour ces ressources, relations/indexes, références uniques, dates cohérentes, échéance dans la période du contrat et montant positif. Suppression interdite ou archive quand liée à une opération financière ; pas de destruction silencieuse de l’historique. Recherche/filtrage/pagination serveur. Création liée et listes contrôlées via API ; contraintes également relues dans le code.
- [x] **Recouvrement.** Dossier lié à une échéance impayée dépassée, pas de doublon actif ; affectation uniquement à un agent actif ; détail présentant assuré, contrat, dette, relances, paiements et historique. CRUD sous contraintes. Transitions nouveau/en_cours/promesse_paiement contrôlées ; clôture seulement à solde nul ; réouverture réservée gestionnaire/admin après correction financière recréant une dette. Parcours de création, transition et clôture contrôlé via API.
- [x] **Paiements et corrections tracées.** Montant positif, jamais supérieur au solde dû, paiement partiel ; ordre de verrous échéance/dossier/paiements et relecture du solde courant. Paiements validés conservés ; annulation seulement gestionnaire/admin avec motif et recalcul. Aucun encaissement bancaire réel. Paiement partiel, surpaiement refusé, annulation/double annulation refusée et réouverture contrôlés via API ; concurrence non mesurée ici.
- [x] **Relances fictives et audit.** Relances rattachées aux dossiers, création/lecture/modification/suppression avant validation selon droits ; aucun e-mail/SMS réellement envoyé. Audit append-only auteur/action/ressource/moment, typé et limité aux ressources du dossier ; aucune modification/suppression exposée ; pas de secret journalisé. Contact fictif et audit contrôlés via API.
- [x] **Dashboard et interface.** KPI réels et filtres période/type/agent ; recherche paginée ; français ; interface responsive, formulaires/dialogues accessibles, chargements, états vides et erreurs ; profils limités à leur périmètre. Pages reliées à l’API, pas de statistiques figées. Compilation et endpoints contrôlés ; rendu interactif navigateur et accessibilité exhaustive restent pour E2E/usabilité.
- [x] **Règles métier testables.** Validation montants/dates, solde, paiement, dette échue, transition, clôture et réouverture isolés dans server/domain/recouvrement.ts sans DB/Express ; date explicite. Affectation, permissions, références et correction tracée complètent les règles. Aucun test unitaire de campagne écrit à cette phase.
- [x] **Documentation et vérification de construction.** README installation Linux/PowerShell, DB/données fictives, rôles, conventions TND et limites ; API_CONTRACT endpoints ; types/build, santé HTTP, statut404 et parcours API ciblé exécutés. Une revue read-only a relié back/front aux critères, problèmes confirmés corrigés. Aucun scanner, rapport de couverture, mesure de charge ou conformité ISO inventé ; aucune publication effectuée.
